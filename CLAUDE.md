# Aprovi (plataforma de estudos) — guia para o Claude Code

O app se chama **Aprovi** (repositório e pasta continuam `plataforma-estudos`). App pessoal e multiusuário para acompanhar estudos de concurso: edital (disciplinas → tópicos com check de concluído), registro de estudos (tempo e questões), ciclos de metas, flashcards no estilo do Anki, cronômetro/timer/pomodoro, histórico e dashboard. Interface e código em **português**.

## Stack

- **Frontend:** React 19 + TypeScript + Vite, Tailwind CSS v4, React Router (`createHashRouter`), TanStack Query, Recharts, lucide-react, sonner (toasts), date-fns (locale `ptBR`), Radix Dialog, dnd-kit (arrastar tópicos), ts-fsrs (agendamento dos flashcards). Só na importação do Anki, carregados sob demanda: fflate (zip), fzstd (zstd) e sql.js (SQLite em WASM).
- **Backend:** Supabase (Postgres + Auth + API REST automática). Não existe servidor próprio: toda regra de acesso está no banco (RLS).
- **Deploy:** GitHub Actions → GitHub Pages a cada push na `main` (`.github/workflows/deploy.yml`). `base: './'` + rotas em hash, então funciona em qualquer subcaminho.

## Banco (Supabase, projeto `qudoenqafdaayrdnxkel`, região sa-east-1)

Tabelas em `public`: `perfis`, `convites`, `disciplinas`, `topicos`, `estudos`, `metas` (metas semanais de minutos e questões, uma linha por usuário), `provas` (nome e data de cada prova/concurso, só para a contagem regressiva), `provas_feitas` (provas já feitas, do Raio-X), `ciclo_metas` e `ciclos` (ciclos de metas), `planner_itens` (do planner, que saiu do app; os dados antigos continuam lá), `materiais` (links de material de cada tópico), `flash_notas`, `flash_cartoes`, `flash_revisoes`, `flash_config` (flashcards). Funções auxiliares em `privado` (fora da API).

- **Cadastro só por convite:** trigger `privado.tratar_novo_usuario` em `auth.users` recusa e-mails fora de `convites` (o Supabase devolve "Database error saving new user", traduzido no front) e cria o `perfil` com o papel do convite.
- **Master:** único que vê/cria/cancela convites e ativa/desativa usuários comuns. Não consegue criar outro master pelo app (só via SQL).
- **Usuário desativado** (`perfis.ativo = false`) perde acesso a todos os dados pelo RLS.
- **Perfil:** `perfis.nome` e `perfis.foto_url`, editáveis pelo próprio usuário (policy `perfis_update_proprio` + grant só nessas colunas e em `ativo`). O trigger `privado.proteger_ativo` impede mudar `ativo` sem ser master e o master de mudar o próprio. Fotos no bucket público `avatares`, pasta `<user_id>/`, 2 MB, jpeg/png/webp; a foto antiga é apagada ao trocar.
- `user_id` tem default `auth.uid()`: **não envie user_id** nos inserts.
- `estudos` guarda `disciplina_id` (obrigatória) e `topico_id` (opcional: estudo da disciplina sem tópico). Com tópico, o trigger `privado.estudo_disciplina_do_topico` força a disciplina do tópico (cliente antigo que só manda o tópico continua funcionando); a policy exige disciplina própria e tópico da mesma disciplina. Nas contas, use `e.disciplina_id` para a disciplina; estudo sem tópico entra nos totais da disciplina e fica fora do resumo por tópico (`resumirPorTopico`).
- Estudo precisa de tempo > 0 ou questões > 0; acertos ≤ feitas (constraints no banco).
- **Ciclos:** `ciclo_metas` (`disciplina_id`, `ordem`, `nome` ≤ 200, `orientacoes` ≤ 4000); `topicos.meta_id` (→ `ciclo_metas`, `on delete set null`; trigger `privado.topico_meta_valida` exige meta da mesma disciplina e do mesmo usuário); `disciplinas.sigla` (≤ 8, opcional); `ciclos` (uma linha por usuário: `sequencia` uuid[] de disciplinas, até 60, a mesma pode repetir; `posicao`; `meta_id` = meta da vez). Migration `20261126000000_ciclos.sql`.
- `planner_itens`: tabela do planner antigo. O planner saiu do app a pedido da usuária (revisões só no Anki); a tabela e os dados ficaram no banco, sem uso.
- **Flashcards:** `flash_notas` (conteúdo; `disciplina_id` = baralho, `topico_id` opcional, `tipo` basico/omissao, `frente`/`verso` em HTML simples, `origem_anki` única por usuário para não duplicar importações); `flash_cartoes` (um por nota no básico, `ordem` 0; um por número de omissão; campos do FSRS: `estado` 0 novo/1 aprendendo/2 revisão/3 reaprendendo, `vence_em`, `estabilidade`, `dificuldade`, `dias_agendados`, `passo`, `repeticoes`, `lapsos`, `ultima_revisao`, `suspenso`, `posicao`); `flash_revisoes` (cada resposta 1–4, estado antes, duração); `flash_config` (novos/dia, revisões/dia, retenção). Apagar a disciplina apaga tudo em cascata.
- **Imagens dos flashcards:** bucket público `flashcards` (5 MB, jpeg/png/webp/gif), pasta `<user_id>/`, nome aleatório; só o dono com conta ativa envia/troca/apaga. No HTML do cartão a imagem é `<img src="<URL pública>">`; `limparHtml` só aceita src que começa com `PREFIXO_IMAGENS_FLASH` (o resto vira "[imagem]"). Ao excluir uma nota ou tirar a imagem de uma nota, o arquivo é apagado se nenhuma outra nota usar (apagar a disciplina inteira deixa os arquivos).
- **Provas feitas:** `provas_feitas` (`nome`, `cargo`, `banca`, `data`, pares `nota_*`/`corte_*` para `objetiva`, `discursiva` e `final`, `situacao` aprovado/classificado/nao_classificado/eliminado/aguardando, `classificacao`, `observacao` ≤ 500, `disciplinas` jsonb `[{ nome, nota, total }]`, `tipo` prova/simulado; tudo opcional menos nome e data; o app hoje só preenche `nota_final`/`corte_final`, situação, classificação e as notas por disciplina). Não tem ligação com `provas`: lançar uma prova antiga não mexe na contagem regressiva.
- **Materiais:** `materiais` (`topico_id`, `titulo` opcional ≤ 120, `url` só http/https sem espaços, ≤ 2000). Apagar o tópico apaga os materiais.
- Mudanças de schema: crie um novo arquivo em `supabase/migrations/` e aplique no projeto (MCP do Supabase ou SQL Editor). Depois rode os advisors de segurança.

## Regras de negócio

- **Tempo de estudo** = soma de `duracao_segundos` no período. **Desempenho** = acertadas ÷ feitas no período. **Progresso no edital** = tópicos `concluido` ÷ total (não depende do período).
- **Saudação:** "Bom dia/Boa tarde/Boa noite, <primeiro nome>!" (hora do aparelho); sem nome, mostra link para o perfil. O avatar não aparece no Início (já está no topo do celular e na barra lateral).
- **Escolher tópico:** `SeletorTopico` sem disciplina escolhida busca em todas, agrupando por disciplina; escolher um tópico de outra disciplina troca a disciplina. Com disciplina escolhida, digitar um nome que ainda não existe mostra no fim da lista "Adicionar “X” em <disciplina>" (setas + Enter também): cria o tópico no fim do edital dessa disciplina (`useCriarTopico`, nível 0) e já o escolhe; para virar subtópico ou mudar de lugar, é na página da disciplina. A janela abre por cima de outro diálogo (`Dialogo` com `sobreposto`), com foco na busca (`focoInicial`) e, no celular, colada no topo (`noTopo`) para o teclado não cobrir a lista.
- **Provas:** card de contagem regressiva no Início com as provas de hoje em diante (mais próxima primeiro); com mais de uma, alterna a cada 6 s com animação (pausa com mouse/foco; sem troca automática se o sistema pede menos movimento). Cadastro no diálogo da engrenagem (`ProvasDialog`). Datas `date` sem fuso: use `lib/provas.ts`.
- **Início (layout):** linha de 4 resumos (`ResumoTopo`: tempo total, desempenho, progresso no edital — cada um com "Neste mês" e variação contra o mesmo trecho do mês passado — e o versículo); faixa larga de Constância (quadradinho por dia, ≥ 20 min = ✓, navegação por janelas; "Ver detalhes" leva ao Raio-X); depois 2 colunas no xl: esquerda Meta da vez (`MetaDaVez`, do ciclo, no lugar do antigo Planejamento de hoje), Estudo semanal (barras seg–dom, Tempo/Questões, navega semanas) e o atalho do Raio-X; direita Provas, Metas semanais e Tempo de estudo (pizza). No celular (abaixo de `sm`) o topo é compacto: saudação menor com o botão "+ Estudo" ao lado e, embaixo, a prova mais próxima numa linha discreta (`ProximaProva`: nome · faltam N dias; o cartão completo continua mais abaixo); depois o versículo (pedido dela: em cima), os três números numa linha só (`ResumoCelular` em `ResumoTopo`: tempo curto por `horasCurtas`, acerto, edital; tocar abre o total e o "Neste mês" com a variação; os cartões grandes e o versículo do grid ficam `hidden sm:grid`). A ordem segue Meta da vez, Constância, Provas, Metas, Estudo semanal, Tempo de estudo, Raio-X (tudo numa coluna flex com classes `order-*`; o grid de 2 colunas é `contents` abaixo do xl).
- **Edital** (`/edital`, página `Edital`): no topo o cartão "Progresso no edital" (X de Y tópicos concluídos em N disciplinas, percentual, barra em `--c-visto` e o ritmo: tópicos com `concluido_em` nas últimas 4 semanas e a média por semana). Depois "Ordenar por" (Ordem do edital, Nome, Maior progresso, Menor acerto) e "Mostrar" (Todas, Em andamento, Concluídas, Não iniciadas), salvos no navegador (`edital:ordem`, `edital:mostrar`), e "Expandir todas / Recolher todas". Cada disciplina é uma linha larga: ícone na cor da disciplina, nome (abre a página da disciplina), acertos / questões com o selo, barra de progresso com o percentual, lápis (editar) e a seta que abre os tópicos ali mesmo (`TopicosDaDisciplina`: check de concluído, numeração e as mesmas colunas da página da disciplina, Questões, Último estudo e Estudo (tempo e nº de sessões), reaproveitadas de `ListaTopicos`; no celular esses números vão embaixo do nome; no pai somam os subtópicos). Tópico com subtópicos tem uma seta para esconder/mostrar os subtópicos (recolhido mostra "(N subtópicos)") e, no alto da lista, "Esconder subtópicos / Mostrar subtópicos" para todos; é a mesma lista salva da página da disciplina (`useRecolhidos`, chave `recolhidos:<disciplina>`). Tópico concluído fica com a linha inteira no verde claro do visto (`bg-visto-fundo`), aqui e na lista da página da disciplina (`ListaTopicos`), com o texto normal, sem riscar. Dentro da linha aberta ficam "Abrir disciplina" e "Excluir disciplina". Adicionar, ordenar e materiais continuam na página da disciplina.
- **Raio-X** (`/raio-x`, página `RaioX`): a análise detalhada da aprendizagem, fora do Início: Heatmap do ano (`MapaCalor`), Por disciplina (`PorDisciplina`: tempo, questões, acerto, progresso no edital) e Pontos de atenção (`PontosAtencao`: até 8 tópicos com menor acerto, com ≥ 5 questões e < 80%, e até 8 em andamento parados há 3 dias ou mais). No menu lateral fica depois de Histórico; no celular, no menu ☰. Abaixo de tudo (aparece mesmo sem edital) fica **Provas que já fiz** (`ProvasFeitas` + `ProvaFeitaDialog`, regras em `lib/provasFeitas.ts`, testadas). O diálogo pede concurso, data, cargo e banca; a **nota de cada disciplina** com o **total** opcional (quanto a disciplina valia; vêm prontas as de `DISCIPLINAS_PADRAO` mais as que o usuário já usou, via `disciplinasConhecidas`, e só entram as preenchidas; nomes comparados sem acento/maiúscula por `chaveDisciplina`); e no fim **Pontuação total** (`nota_final`), **Nota de corte** (`corte_final`), Classificação e Situação. A lista mostra a pontuação, o corte e a distância ("2,5 acima do corte" / "3 abaixo do corte"); o resumo conta provas feitas, quantas no corte ou acima e quando faltou menos; com 2 ou mais provas comparáveis aparece o gráfico de barras pontuação × corte em ordem de data; e a tabela "Por disciplina" (`comparacaoPorDisciplina`) cruza disciplina × prova com o aproveitamento nas faixas de acerto ("80%, 8 de 10"; sem total, só a nota), traço onde a prova não teve a disciplina e a coluna Geral (aproveitamento somando as provas com total; sem nenhum total, a média das notas). Logo abaixo vem **Simulados**: o mesmo componente com `tipo="simulado"` (coluna `provas_feitas.tipo`, 'prova' | 'simulado'; `doTipo` separa as listas). Muda o texto, o formulário não tem Situação (e chama `cargo` de "Concurso que você está treinando" e `banca` de "Curso ou banca"), o resumo mostra simulados feitos, melhor pontuação e o último com a variação contra o anterior (`resumoSimulados`), e o gráfico aparece só com a pontuação (a barra de corte entra se algum simulado tiver corte; rótulo com dia/mês). As disciplinas sugeridas são compartilhadas entre provas e simulados. As colunas de objetiva/discursiva e `observacao` existem no banco mas o diálogo não preenche mais (a lista ainda mostra se houver dado antigo; salvar não apaga). Heatmap: 0: < 20 min, 1: < 1h, 2: < 2h, 3: < 4h, 4: ≥ 4h. Períodos em `lib/periodos.ts`.
- **Ciclos** (`/ciclos`, página `Ciclos`; no menu no lugar do Planner, e na barra de baixo do celular): pedido da usuária para parar de acumular matérias. Cada disciplina é dividida em **metas**, grupos de assuntos seguidos do edital verticalizado; **assunto** = tópico sem subtópicos (o tópico com subtópicos é só título de seção e não entra em meta; subtópico criado depois herda a meta do tópico de cima). **Meta cumprida** = todos os assuntos dela concluídos (o mesmo check do Edital; o que já foi estudado conta). O **ciclo** é a ordem em que as disciplinas se revezam (pode repetir; a dela foi montada pelo peso da prova: peso 2 duas vezes, bem espaçado, peso 1 uma vez; Simulados e Revisão ficou de fora); a **meta da vez** é a primeira meta pendente da disciplina na posição atual; quando ela é cumprida, `useCicloDados` grava a passagem para a próxima posição com meta pendente e avisa ("Meta cumprida! Agora é DA · Meta 1."). "Pular" passa sem cumprir (a meta volta na próxima vez da disciplina).
  - Tela: cartão **Meta da vez** (disciplina, "SIGLA · Meta N — nome", barra dos assuntos concluídos, Começar → Estudar com `state.comecar` e o primeiro assunto pendente, Ver assuntos, Pular); **Quadro de metas** (linha por disciplina com sigla, cumpridas/total e a tesoura de dividir; quadradinho por meta: cumprida pintada na cor da disciplina, da vez com contorno, com assunto concluído levemente tingida; aviso de assuntos sem meta; disciplinas ainda não divididas embaixo); **roda do ciclo** (`RodaCiclo`, bolinhas na cor da disciplina com a sigla, setas no sentido do ciclo, a da vez com anel; mouse em cima ou toque mostra no meio a próxima meta daquela disciplina, com "Ver assuntos"). No xl a roda fica numa coluna à direita.
  - **Detalhe da meta** (`MetaDialog`): assuntos com check de concluído, numeração do edital, questões (acertos/feitas com o selo) e tempo de cada um (todos os estudos já registrados contam), links de material (`ChipsMateriais`, "Adicionar material" abre o `MateriaisDialog` do tópico), "Registrar questões" (abre o `EstudoDialog` com disciplina, assunto e categoria Questões; entra no Histórico e no Raio-X), "Estudar"; total de questões da meta; **Orientações** (texto livre da meta, salvo ao sair do campo); setas para a meta anterior/próxima da disciplina. O detalhe sai da frente enquanto o diálogo de estudo ou de materiais está aberto.
  - **Dividir em metas** (`DividirMetasDialog`): a lista do edital com os títulos de seção; cada meta é uma caixa com o nome editável e concluídos/total; a tesoura num assunto começa meta nova ali, o botão de juntar une com a de cima; atalhos 1 por tópico principal (padrão; nome = o tópico principal), 1 por assunto, juntar de N em N, tudo numa meta. Salvar mantém a meta (id, nome, orientações) que o primeiro assunto do trecho já tinha; trechos novos viram metas novas e as que sobram são apagadas. "Desfazer as metas" apaga a divisão da disciplina.
  - **Editar ciclo** (`EditarCicloDialog`): ordem (subir, descer, tirar, adicionar; a mesma disciplina pode entrar mais de uma vez), peso 0/1/2 de cada disciplina (salvo no navegador, `ciclo:pesos`) com "Montar a ordem pelo peso" e as siglas (vazia = sugerida por `sugerirSigla`). Salvar mantém a disciplina da vez.
  - Ao configurar, o ciclo dela ficou com 20 etapas (DT, PORT, DC, RLM, DPT, DA, DH, CIV, DPC, LEG, DT, PORT, DC, INFO, DPT, DA, PCD, CIV, DPC, DISC) e cada disciplina dividida em 1 meta por tópico principal, para ela ajustar.
- **Planner retirado** a pedido da usuária (as revisões ficam só no Anki): página, cartões, diálogos, `lib/planner.ts`, `usePlannerAcoes`, o "Programar revisões" e o "Só marcar como feito" do Salvar estudo e o vínculo do cronômetro com o planner saíram. `/planner` redireciona para `/ciclos`.
- **Salvar estudo** (`EstudoDialog`, diálogo largo `max-w-3xl`): no topo o dia pelos botões Hoje / Ontem / Outro ("Outro" mostra o campo de data e hora; a hora é a de agora num registro novo); linha Categoria → Disciplina → Tempo de estudo; depois Tópico na linha inteira, a caixa Questões (Feitas / Acertos, com o selo do percentual) e a Observação; no rodapé, "Salvar e criar novo" à esquerda e os botões à direita. **Tempo de estudo** é um campo só, `hh:mm:ss`: os dígitos entram pela direita (1, 2, 0, 7 → 00:12:07), o cursor fica sempre no fim e ao sair o valor é normalizado (90 s → 00:01:30); o tempo é gravado com os segundos (o do cronômetro chega exato). `formatarDuracaoExata` ("11min32s") mostra os segundos no registro do Histórico, no aviso do diálogo e no "de estudo" do timer/pomodoro; os totais continuam em minutos (`formatarDuracao`). Aceita `iniciais.categoria` (o "Registrar questões" da meta chega com Questões). **Categoria** (`estudos.categoria`, texto ≤ 40, opcional; regras em `lib/categorias.ts`): Teoria, Questões, Revisão, Flashcards e as que o usuário criar pela opção "Nova categoria…" (vira um campo de texto; o X volta para a lista). Não há tabela de categorias: a lista é a padrão mais as já usadas em algum estudo (`categoriasConhecidas`); nome digitado igual a um existente, sem contar acento/maiúscula, usa o existente. Aparece como etiqueta no Histórico. **Tópico opcional só na categoria Flashcards** (rótulo "Tópico (opcional)", opção "Sem tópico" no seletor; no Histórico aparece "Sem tópico"); nas outras categorias o tópico continua obrigatório. Interruptor "Salvar e criar novo" (preferência salva no navegador, `estudo:criar-novo`). Ligado, ao salvar o diálogo continua aberto, mostra o que foi salvo e abre um registro em branco mantendo categoria, disciplina e dia; tempo do cronômetro e item do planner valem só para o primeiro registro. Observação com contador de 500 caracteres.
- **Flashcards** (`/flashcards`, `/flashcards/:id`, revisão em tela cheia fora do Layout em `/flashcards/estudar/:escopo` com `escopo` = id da disciplina ou `todos` e `?topico=`):
  - Agendamento FSRS (ts-fsrs) com passos do Anki: aprendizado 1 min e 10 min, reaprendizado 10 min, retenção padrão 90%. Botões Errei/Difícil/Bom/Fácil mostram o próximo intervalo. Atalhos: espaço/enter mostra a resposta e depois vale "Bom", 1–4, Ctrl+Z desfaz, E edita.
  - Fila (`lib/flashcards/fila.ts`): aprendizado vencido primeiro; depois revisões do dia e novos intercalados, com limite diário por baralho (o que já foi feito hoje desconta); sem mais nada, aprendizado que vence em até 20 min é antecipado. Dia = dia do aparelho.
  - A sessão trabalha numa cópia dos cartões e grava cada resposta em fila (update do cartão + insert da revisão, com id gerado no app), sem recarregar tudo; ao sair, invalida os dados. Desfazer volta o cartão e apaga a revisão.
  - Editor (`CampoRico`): imagem pelo botão, colando (print da tela) ou arrastando; o "Salvar" espera o envio terminar.
  - **Ordem da lista do baralho** (`BaralhoFlash`, regras em `lib/flashcards/ordenacao.ts`, testadas): seletor ao lado dos filtros com Mais antigos (padrão), Mais recentes, Alfabética A–Z / Z–A, Próxima revisão e Tópico (ordem do edital); a escolha fica salva no navegador (`flash:ordem`). A alfabética usa o texto da frente, compara número como número (Art. 9º < Art. 11-A < Art. 855) e ignora acento, maiúscula e pontuação no começo. Só muda a lista; a fila de estudo não muda.
  - **Fixar um lado** (`NotaFlashDialog`, só em cartão novo): o botão "Fixar" ao lado de Frente e de Verso mantém aquele lado preenchido depois de salvar, para criar vários cartões do mesmo assunto; ligar um fixar liga também o "Salvar e criar novo" (`flash:criar-novo`). O fixar não fica salvo: volta desligado ao abrir o diálogo.
  - **Marca-texto:** o botão do marca-texto abre a paleta (amarelo, verde, azul, rosa, lilás, laranja, em tons pastéis) e "Tirar grifo"; seleciona o trecho e toca na cor. Fica gravado como `<mark class="grifo-<cor>">` (cores em `CORES_GRIFO`, `lib/flashcards/html.ts`; tokens `--c-grifo-*` e `--c-sobre-grifo` no `index.css`, texto grifado sempre escuro nos dois temas). O `limparHtml` mantém o `<mark>` só com classe conhecida (outra vira amarelo) e converte trecho com cor de fundo no `style` (grifo do Anki, ao importar ou colar) para a cor pastel mais próxima (`corDoFundo`); branco, cinza e escuro não viram grifo. Grifar por cima de um grifo corta o antigo em volta do novo (sem aninhar).
  - **Cor, tamanho e alinhamento do texto** (`CampoRico`): botões de alinhar à esquerda / centralizar / justificar (valem para o parágrafo; clicar no que já está tira o alinhamento), "Tamanho do texto" (Normal, Grande, Muito grande; o normal da revisão é 1,1rem, o antigo "Pequeno", que saiu a pedido da usuária) e "Cor do texto" (vermelho, laranja, verde, azul, roxo, rosa e "Cor normal"). Ficam gravados como classes de lista fechada: `<span class="cor-<cor>">`, `<span class="tam-grande|enorme">` (um `tam-pequeno` gravado antes é descartado e o trecho fica normal) e `class="alinha-esquerda|centro|justificado"` no bloco (listas em `lib/flashcards/html.ts`; tokens `--c-texto-*` no `index.css`, claros no tema escuro e escuros dentro de grifo). O `limparHtml` mantém só essas classes e converte cor (`style` ou `<font color>`) e `text-align` vindos de fora para a classe mais próxima; preto/cinza e alinhamento à direita são descartados. Na revisão o padrão é centralizado, então "esquerda" e "justificado" mudam o cartão lá também.
  - **Digitar a resposta** (`flash_notas.tipo = 'digitar'`, migration `20261125000000_flash_digitar.sql`; pedido da usuária, como o "Básico (digitar a resposta)" do Anki): frente e verso com um cartão só. Na revisão aparece o campo "Digite a resposta" (com foco; Enter ou "Conferir resposta" revela) e, no lugar do verso, `ComparacaoDigitada` (`ConteudoCartao.tsx`): selo Resposta certa / Quase (só acento, maiúscula ou pontuação) / Resposta diferente / Você não digitou nada, o que foi digitado (certo em verde, a mais ou trocado em vermelho riscado) e a resposta certa (o que faltou em amarelo sublinhado). Regras em `lib/flashcards/digitar.ts` (comparação letra por letra pela maior subsequência comum, espaços repetidos e nas pontas não contam, acima de 2000 caracteres não alinha), testadas. A comparação usa o texto puro do verso; se o verso tiver imagem, ele aparece também. Os botões 1–4 continuam sendo escolha da pessoa. Editando, dá para trocar entre Frente e verso e Digitar (omissão não troca). A importação do Anki ainda traz esses cartões como frente e verso.
  - Omissão: `{{cN::texto}}` ou `{{cN::texto::dica}}`; editar a nota cria/apaga os cartões conforme os números. HTML sempre limpo por `limparHtml` (só tags simples, sem atributos, fora o src das imagens e as classes do marca-texto, da cor, do tamanho e do alinhamento) ao salvar, importar, colar e de novo ao exibir.
  - Importação do Anki (`lib/flashcards/anki.ts`, roda no navegador): .apkg/.colpkg nos formatos novo (`collection.anki21b`, zstd, esquema 18) e antigo (`collection.anki21`/`.anki2`), e .txt de notas em texto puro. Baralho "A::B" sugere disciplina A e tópico B (ignorando a numeração do edital). Mantém o progresso: revisões viram estado 2 com o mesmo vencimento e intervalo; estabilidade/dificuldade do FSRS do Anki quando existem, senão aproximadas (estabilidade = intervalo; dificuldade pelo fator de facilidade). Aprendendo no Anki entra como novo. Imagens do pacote (índice "media": JSON no formato antigo; protobuf + zstd no novo, arquivos também em zstd) ficam como `anki-midia:NOME` até a gravação, que envia cada uma (4 por vez, reduzidas a 1600 px/WebP quando grandes ou em formato não aceito) e troca pelo endereço. Notas importadas antes, que ficaram com "[imagem]", recebem as imagens ao importar o mesmo arquivo de novo (só se ainda tiverem o "[imagem]"). Imagens citadas mas ausentes do pacote (ou vindas de .txt) viram "[imagem]", com aviso. Cartões invertidos ficam de fora (aviso na tela). Já importadas (mesmo guid; no .txt sem guid, mesma frente) são puladas. Grava em lotes; se um lote falhar, desfaz as notas daquele lote.
  - Estatísticas próprias (não entram no histórico nem no tempo de estudo): para hoje, revisados hoje, acerto, sequência de dias, revisões em 30 dias, cartões por estado (jovem < 21 dias ≤ maduro) e previsão de 7 dias.
- Faixas de acerto: ≥ 80% verde, 60–79% amarelo, < 60% vermelho (`nivelAcerto` em `lib/utils.ts`).
- Pomodoro: só o tempo de foco conta como estudo; ao fim de cada fase o relógio para e espera o usuário.
- **Alarme:** ao fim do timer e de cada fase do pomodoro toca um alarme (quatro bipes a cada 2 s, com vibração onde existe) por até 1 minuto ou até parar: botão "Parar alarme" em Estudar e na janelinha (que abre sozinha), ou qualquer ação no relógio (iniciar, zerar, pular, trocar modo). `alarmeTocando`/`pararAlarme` no `useCronometro`. O som é gerado na hora (Web Audio), liberado no clique de Iniciar; com o app em segundo plano ou a tela bloqueada o navegador segura o relógio e o alarme só toca ao voltar.
- **Menu Leis retirado** a pedido da usuária: páginas, componentes, `lib/leis.ts`, rotas, o filtro `?lei=` da revisão e o que o editor (`CampoRico`, `NotaFlashDialog`, `limparHtml`) tinha só para as leis saíram do código. As tabelas `leis` e `lei_linhas` foram apagadas do banco (migration `20261124000000_remove_leis.sql`). Os flashcards criados das linhas ficam nos baralhos.
- **Navegação no celular** (`Layout`, abaixo de `lg`): topo só com ☰, logo e a foto (botão de 44 px redondo, foto de 34 px; ativa ganha um anel) que leva ao Perfil. O ☰ abre o `MenuCelular` (Radix Dialog na lateral esquerda, entra deslizando, fecha ao tocar fora, com Esc, no X ou ao trocar de tela): cartão do perfil, todas as telas (Usuários só para o master), Tema e Sair. A barra de baixo tem só 4 atalhos (`ATALHOS_CELULAR`: Início, Edital, Ciclos, Flashcards); o Estudar fica no botão redondo do cronômetro.
- **Botão do cronômetro / mini cronômetro** (`MiniCronometro`): em todas as telas do Layout, menos Estudar, fica fixo no canto inferior direito (no celular, acima da barra de baixo). Com o relógio zerado é um botão redondo com o ícone do cronômetro que abre a tela Estudar (substituiu o botão "Estudar agora" do Início); com tempo no relógio (rodando ou pausado) vira a janelinha. Tocar no tempo volta para Estudar. Fica dentro do `<main>` com um espaço no fim da página para não cobrir o último conteúdo. Contagem regressiva arredonda para cima (mostra 00:01 até acabar).
- **Subtópicos (até 3 níveis):** `topicos.nivel` (0 tópico, 1 subtópico, 2 subtópico do subtópico). A lista da disciplina é única e ordenada; cada item pertence ao item acima com um nível a menos. Regras em `lib/topicos.ts` (numeração 4 / 4.2 / 4.2.1, usada também nas listas de escolha de tópico via `rotuloSelecao(t, todos)`; arrastar leva a subárvore; recuar/avançar; posição digitada é entre os irmãos) — testadas com casos de borda. Seta para recolher/expandir, salva no navegador por disciplina. Nos números do item pai entram todos os subtópicos. Importação: cada recuo maior (espaços ou tab) desce um nível.
- **Ordenar tópicos só no modo de edição:** na página da disciplina, o botão "Editar ordem" (canto direito da linha dos filtros; no celular só "Editar") liga o modo em que aparecem a alça de arrastar e o número editável, e muda o filtro para Todos; "Concluir" desliga. Fora dele o número é só texto, para não mudar a ordem sem querer. O modo não fica salvo.
- **Materiais do tópico:** no menu ⋮ de cada tópico, "Adicionar material" / "Materiais (N)" abre o diálogo para colar um link (PDF, texto próprio, vídeo, Drive…) com nome opcional; dá para editar e remover. Os links aparecem como etiquetas embaixo do nome do tópico (até 3, depois "+N") e na tela Estudar quando o tópico está escolhido (num subtópico, aparecem também os links do tópico pai e do avô, nessa ordem: `materiaisDaFamilia` em `lib/materiais.ts`, testada); abrem em outra aba com `rel="noopener noreferrer"`.
- Ordem dos tópicos: `useReordenarTopicos` grava a lista inteira numa só requisição (upsert por `id`, `ordem` = posição) com atualização otimista.
- Os dados são carregados inteiros por usuário (`buscarTodos`) e agregados no front. Escala pessoal, funciona bem até dezenas de milhares de estudos.

## Visual

Paleta lilás definida em `src/index.css` como variáveis CSS (`--c-*`) e exposta ao Tailwind (`bg-primaria`, `text-tinta`, `bg-nevoa`…). Tema escuro via classe `.dark` no `<html>`. Os tokens do planner antigo (`--c-cabecalho`, `--c-estudo`, `--c-resumo`, `--c-exercicios`) ficaram no CSS sem uso; `--c-revisao` é a cor dos "Novos" nos flashcards. **Cores das disciplinas:** 24 opções em `CORES_DISCIPLINA` (`lib/utils.ts`, com nome em `NOME_COR_DISCIPLINA`) mais "outra cor" pelo seletor do aparelho no `DisciplinaDialog`; a cor vai no `style` (edital, planner, gráficos) e `corSobre` decide se o que fica por cima é claro ou escuro. Marca Aprovi: design system em https://claude.ai/artifact/87BZa5haYWekHRuoXWUecs (logo, cores, tipografia e regras de uso). Fonte única: Outfit (400–600), sem serifada; não existe mais `font-serif`. O verde `--c-visto` (`bg-visto`, `text-visto-texto` para texto pequeno, `bg-visto-fundo`) é o do logo e só aparece no que foi concluído: check do tópico (classe `visto` no checkbox), item do planner feito, barra do planejamento de hoje. `--c-bom` continua sendo só a faixa de acerto ≥ 80% e avisos de sucesso. Use os tokens, nunca cores soltas. Controles nativos seguem o tema por `color-scheme` (no `.dark`); as opções do `<select>` têm fundo e cor dos tokens em `index.css`, porque o Chrome do Windows abria a lista branca com texto claro no tema escuro.

Largura: o conteúdo ocupa toda a tela ao lado do menu (o `<main>` do `Layout` não tem `max-w`); só formulários e o relógio limitam a própria largura (Perfil, Estudar, revisão dos flashcards); a visão Dia do planner também ocupa a largura toda. Para telas muito largas existe o breakpoint `3xl` (112rem), (o Edital não usa mais grid: é uma lista de linhas largas); o heatmap aumenta os quadradinhos até 28 px para preencher a largura.

## Convenções

- Nomes de variáveis, componentes e textos em português; textos curtos, voz ativa, sentence case.
- Erros mostrados ao usuário dizem o que aconteceu e como resolver.
- Sempre `npm run build` sem erros antes de commitar.
- Grids sempre com `grid-cols-1` (ou `minmax(0,…)`) na base, para conteúdo longo não estourar a largura no celular.
